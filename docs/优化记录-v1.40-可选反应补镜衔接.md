# v1.40｜可选反应补镜衔接

日期：2026-10-28。基线：main 26a723c（v1.39）。

## 来源与边界

用户要求将[分享聊天中的方法](https://chatgpt.com/s/cx_6ae1b97c0be881918de13dd49314be7c)合入，保留适用条件、验收规则，不把4秒、正脸、无对白设为硬要求。整理依据是两个对白场景的提示词迭代及用户反馈，未取得最终补镜成片。线稿画风偏移是案例反馈；方法效力属于项目经验，不标为官方能力或已通过视频验证。

## 修改

- transition-routes第二节增加路线5：独立反应覆盖A→R→B，包含适用与停止条件、素材用途、机位与状态、生成/剪辑时长分工、交付和三项验收。
- 原稿长镜头优先，新增/增时等按入口唯一确认政策；未采纳只建议、不阻塞其他段；不以特写隐藏道具或动作状态矛盾。
- 明确人物数量、镜头数量、时长、脸向、声音均按原稿/任务选择，保留已有连续对白和原音轨；亚秒切点不宣称可靠生成，净时长独立核算。
- SKILL入口增加定向触发，制作核心只加查阅指引，自检索引接到路线5；普通接缝不默认采用，不增加专项必读负担。README登记v1.40。

## 验证

修改前只读应用检查5案：通用保护能处理长镜头、授权和状态冲突，但缺少可检索的补镜路线、两侧接缝与净反应时长的完整规范。修改后由独立检查者复用相同5案核对，均能找到路线并正确处理授权、原稿长镜头、状态冲突及净时长。复核发现的两处直接关联问题已同步：衔接表加入“用户已确认”采用状态，并与实片验收分开；旧“先补关键图”限定于拟连续/直接匹配或首尾帧桥接，不强加给可切镜的反应覆盖。

结构验证：仓库check_skill.py与官方quick_validate.py通过；本地Markdown链接、代码围栏有效，适配模块逐字未改。普通必读工作集14,355字符，比v1.39仅增加85字符，低于仓库15,000字符预算。

未生成图片或视频，未做真实A→R→B的画面、声音与节奏验收。文本/结构通过不能代替出片验证。
