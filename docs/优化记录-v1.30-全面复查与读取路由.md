### v1.29 自己写错的一处

- v1.29 在 scene-blocking-axis 第六节写了“画面左右只对交代全景的机位成立，切到侧向机位时换算该镜的左右”。这不对：机位守在轴线同一侧时，正反打两人的左右本来就不变。改为：轴线上两人左右不变；不在这条轴线上的第三、第四人，换机位后左右可能变，以房间位置为准。

## 三、执行成本（“算法复杂度”）优化

### 基准（v1.29）

- 全部规则约 12.8 万字。原来 18 个参考文件都写“必须读取”，一次典型任务（四人文戏、Seedance、有人物和场景图、两段、某集第一段）实际要读约 10.7 万字，占 83%。
- 输出端：诊断 25 类逐项写；待确认槽位列近 30 个参数，每个 5 个选项；八层库全文每次复述；自检 225 条逐条打勾。
- 槽位把景别、机位、运镜、光源方向、情绪曲线这类本该由 skill 设计的项也列成“缺失参数”。剧本输入几乎每次都超过 3 项，要么多一轮问答，要么执行方自行判定“无需选择”后全部用保守默认（第31集稿全部固定机位，就有这个原因）。

### 改动

| # | 内容 | 落点 |
|---|---|---|
| P1 | 读取路由：第一层每次读（adapter、自检）；第二层有人物的文戏读（镜头语法、对话戏、表演目标、微表情）；第三层按条件表读，并允许只读指定章节（例如轴线文件读第一、二、六、七节，运镜库第六节只查用到的那一种，情绪速查只读用到的那一组，转场文件只读第零节和段间衔接表） | SKILL “参考文件与读取路由”；5 个参考文件的开头说明同步 |
| P2 | 时长评估公式写进 SKILL 阶段 1，“够用”时不必读润色文件 | SKILL 阶段 1 |
| P3 | 槽位分两类：必须问用户的（画幅、任务类型、时长、资产与声线、是否要音乐、片头片尾、会改变剧情的事实）；由本 skill 设计、不列槽位的（景别、机位、运镜、构图、表演、情绪过渡、光影写法）；本项目前面确认过的沿用 | SKILL 输入协议、阶段 3 |
| P4 | 诊断只写查出问题的类别，其余合并一句 | SKILL 输出格式一 |
| P5 | 八层库在 Seedance 下不再整段复述，只写一句已核对；用户要求时再给全文 | SKILL 输出格式四 |
| P6 | 自检只核对适用专项，输出只写结果（每个专项一行“通过”，有问题的单列），能数的项按实际文本数 | 自检开头说明；打斗条目移入“有打斗时追加” |
| P7 | 阶段 4 原来的一整段长句改为 11 步，每步对应路由 | SKILL 阶段 4 |

### 效果估算

- 同一典型任务的读入：约 10.7 万字降到约 7.5 万字（-30%）。
- 输出：自检从 225 行降到每个适用专项一行加问题行；诊断、八层库各省去固定篇幅；镜头类参数不再触发一轮槽位问答。
- 以上是按文本量估算，实际耗时要用同一输入、新旧两版各跑一次对比。
