# v1.43 执行流程优化：有向无环 + 状态记忆（2026-11-02）

问题：每次执行耗时非常长。原因不是模型慢，是执行方式慢——主流程每段都要重新读规则、重新算时长、重新查空间、重新核对覆盖，专项文件又各做一遍主流程的检查，耗时随“段数 × 触发文件数 × 检查项”增长。单文件排查看不到这个跨文件累积，所以之前排查给不出结论。

## 改动

- 新增 `skills/storyboard-prompt-optimizer-l5/references/execution-flow.md`：阶段有向无环图、路由决策树、单一所有者表、内部工作状态与记忆规则、排除注入只做一次。
- 阶段单向推进：恢复依据 → 分配承载并估时 → 设计 → 写段 → 单次校验 → 交付，不回读、不重跑已通过阶段；局部修改只回退到受影响段的起点。
- 路由改成决策树：先按段类型定主文件，再最多补一个次文件，优先级为剧本指定 > production-core.md > 专项文件；同一触发在同一集里只进一次，第二次直接复用结论。
- 单一所有者表：每条规则只留一个定义文件，其他文件只写指针；冲突时以所有者为准。v1.43 先定所有权和优先级，不一次性删遍 28 个文件的复述句，避免改动面失控。
- 工作状态记忆：段清单、进入/离开状态、空间锁版本、声线、时长预算、已查专项、已通过检查；已通过且未改动的段直接跳过，用户只改某段时只重算脏段及其依赖段。耗时从“段数 × 触发文件数 × 检查项”降到“段数 × 检查项 + 首次触发专项数”。
- 校验只做一次：production-core.md“交付前内部检查”为唯一规范检查表；self-check-checklist.md 改为该表的索引，diagnostic-audit.md 改为该表结果上的评分视图，两者不再重新跑覆盖、时长、空间核对。
- 排除注入只做一次：注入点唯一为 seedance-2-5-adapter.md 第十一节，专项不再各写排除句。
- 顺带修掉声线硬矛盾：dialogue-scene-continuity.md 第一节第 2 条补限定，年龄、性别、口音仅当剧本或已有角色信息给出时才写；声线所有者为 SKILL.md 确认政策第 3 条。
