# 执行流程：有向无环 + 状态记忆（v1.43）

为什么之前慢：不是模型本身慢，是执行方式慢。主流程每段都要重新读规则、重新算时长、重新查空间、重新核对覆盖，专项文件又各做一遍主流程的检查，耗时随“段数 × 触发文件数 × 检查项”增长。Codex 单文件排查看不到这个跨文件累积，所以给不出结论。本文件把执行改成：按阶段单向推进，每项只算一次，结果记入工作状态，未改动段不重算。

## 一、阶段有向无环图

只允许按箭头单向走，不回读、不重跑已通过阶段；局部修改只回退到受影响段的起点。

```
恢复依据 → 分配承载并估时 → 设计 → 写段 → 单次校验 → 交付
   ↑            ↑               ↑        ↑         ↑
 SKILL确认   SKILL保护+      production- adapter  production-
 +project-   script-polish    core      格式+     core交付前
 state       时长评估                    排除一次  内部检查
                                             注入
```

- 恢复依据：SKILL.md 确认政策 + project-state.md；已确认参数直接沿用，不重复问。
- 分配承载：SKILL.md 剧本保护做条目标号；script-polish-capacity.md 只做时长评估，不改剧本。
- 设计：production-core.md 为主；专项只在核心解决不了时按第二节决策树进，且只补细节。
- 写段：seedance-2-5-adapter.md 定格式、时间戳、素材绑定；排除内容只在这里注入一次（见第五节）。
- 单次校验：production-core.md“交付前内部检查”为唯一规范检查表；self-check-checklist.md 只是该表的索引，diagnostic-audit.md 只是该表结果上的评分视图，两者都不再重新跑覆盖、时长、空间核对。
- 交付：SKILL.md 工作与交付的五项顺序；校验结论只写一句，不展开已通过项。

## 二、路由决策树（代替线性查表）

SKILL.md 路由表仍是触发条件清单，但执行时按优先级走决策树，不把命中行全部展开：

1. 先按段类型定主文件：一集一段普通文戏 → production-core.md；打斗 → combat-texture-engine.md；特殊转场 → transition-routes.md；资产/关键帧 → reference-asset-prep.md；非 Seedance → negative-prompt-library.md。
2. 再按触发条件最多补一个次文件：例如对话戏主文件是 production-core.md，次文件是 dialogue-scene-continuity.md；情绪措辞困难时次文件是 micro-expression-engine.md，而不是同时展开 acting-objectives.md、emotion-quick-reference.md、emotion-arc-triggers.md。
3. 优先级写死：剧本指定 > production-core.md > 专项文件。专项只能补核心没覆盖的细节，不能推翻核心已定的选镜、运镜、时长、空间结论；冲突时以主文件和第三节所有者表为准，不做交叉比对后二选一。
4. 同一触发在同一集里只进一次：第二次出现相同触发（例如第二段又是普通问答），直接复用第一段已定的接话、声线、运镜决策，不重新读专项文件；只有触发条件本身变了（例如从普通问答变成抢话、爆发）才重新进专项。

## 四、内部工作状态与记忆规则（不交付，只内部用）

每集内部维护一张工作状态，字段如下；状态本身不写进交付稿：

| 字段 | 内容 |
|---|---|
| 段清单 | 段号、原稿条目范围、是否受阻及原因 |
| 进入/离开状态 | 位置、姿态、视线、占手、道具持有者、声音（按 project-state.md 的采用/验证分开记） |
| 空间锁版本 | 场景图版本、修复图版本（以用户确认的修复图为准） |
| 声线 | 每角色已定声线句（逐字复用，不重写） |
| 时长预算 | 每段台词秒数、动作秒数、反应秒数、余量、结论（够用/勉强/不够） |
| 已查专项 | 已进过的专项文件、命中条件、已定结论 |
| 已通过检查 | 规范检查表里已通过的项、对应段号、对应版本 |

记忆规则：

- 已通过项且该段未被改动 → 后续阶段直接跳过，不重算、不重读文件。
- 用户只改某段 → 只把该段及其依赖段标脏，只重算脏段；其他段的已通过项继续有效。这与 SKILL.md“局部修改只重写受影响段”一致，只是把范围从“重写”扩展到“重算”。
- 专项结论按触发条件缓存：同一集里同一触发第二次出现，直接复用结论；触发条件变了才重新进专项。
- 校验阶段只做两件事：核对脏段、核对跨段接续（上一段离开状态是否等于下一段进入状态）。已通过的单段内部项不再逐项重跑。

这样耗时从“段数 × 触发文件数 × 检查项”降到“段数 × 检查项 + 首次触发专项数”，集数越长、段数越多，省得越多；单段简单任务本来就只读 3 个工作集文件，耗时变化不大，慢主要体现在多段复杂集上。

## 五、排除注入只做一次

- 注入点唯一：seedance-2-5-adapter.md 第十一节，在写段时把剩余风险压成末尾一句排除，不粘贴八层全文。
- 专项文件不再各写排除句：需要排除时只在工作状态里记一条风险，写段时统一注入；注入后记入已通过检查，校验阶段只核对“已注入、未重复、未矛盾”。
- 默认每段“不要字幕、水印文字”仍按 adapter 规则；用户明确要求某段生成文字时只覆写该段这一条（见 opening-ending-title.md）。
