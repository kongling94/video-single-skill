# 执行流程：阶段推进与逐镜状态（v1.43 + 分支连续性修正）

按阶段推进，复用已读规则与有效结果；动态状态按实际事件更新。2026-11-04 分支修正来自用户提供的连续性失败记录，不是模型能力保证，文本验证与出片验证分开。

## 一、阶段有向无环图

以下是正常顺序。分配时先估时，调度落地后核实负载；校验发现矛盾时回到受影响步骤，更新本段与依赖段，再验修改处及接缝，不重跑未受影响项。

```
恢复依据 → 分配承载并估时 → 设计 → 写段 → 单次校验 → 交付
   ↑            ↑               ↑        ↑         ↑
 SKILL确认   SKILL保护+      production- adapter  production-
 +project-   script-polish    core      格式+     core交付前
 state       时长评估                    排除一次  内部检查
                                             注入
```

- 恢复依据：SKILL.md 确认政策 + project-state.md；已确认参数直接沿用，不重复问。
- 分配承载：SKILL.md 剧本保护做条目标号；script-polish-capacity.md 只做时长评估，不改剧本。
- 设计：production-core.md 为主；转向、进出场或多人状态变化执行第八节；其他专项按第二节只读命中章节。
- 写段：seedance-2-5-adapter.md 定格式、时间戳、素材绑定；排除内容只在这里注入一次（见第五节）。
- 校验：production-core.md“交付前内部检查”为唯一入口，命中第八节时必做逐镜状态检查；self-check-checklist.md 仅作定位索引，diagnostic-audit.md 作评分视图，不再重复执行另一套检查。
- 交付：SKILL.md 工作与交付的五项顺序；校验结论只写一句，不展开已通过项。

## 二、路由决策树（代替线性查表）

SKILL.md 路由表仍是触发条件清单，但执行时按优先级走决策树，不把命中行全部展开：

1. 先按段类型定主文件：一集一段普通文戏 → production-core.md；打斗 → combat-texture-engine.md；特殊转场 → transition-routes.md；资产/关键帧 → reference-asset-prep.md；非 Seedance → negative-prompt-library.md。
2. 按需补读具体章节，不设“最多一个次文件”的硬上限。状态变化先执行第八节；过肩/头身转向困难查 scene-blocking-axis.md 第七、十节，人物重新入画或离场查 dialogue-scene-continuity.md 第二节，交接占手冲突查 scene-prop-continuity.md；不为命中关键词通读全库。
3. 用户要求与入口政策优先；规则定义按第三节所有者，production-core.md 是入口，专项补细节。发现设计与定义冲突时修正设计，不能因草稿已定就保留错误；同场合并不能覆盖第八节的可达性和负载要求。
4. 同一规则读过可复用；每次应用仍结合当前人物、动作目标、机位和状态，不能照搬上一处接话、运镜或站位结果。

## 四、内部工作状态与记忆规则（不交付，只内部用）

每集内部维护一张工作状态，字段如下；状态本身不写进交付稿：

| 字段 | 内容 |
|---|---|
| 段清单 | 段号、原稿条目范围、是否受阻及原因 |
| 事件状态 | 按第八节逐镜维护位置、坐站、身体朝向、头向/视线、可见性、占手与持物；段末用于跨段接续，采用/验证按 project-state.md 分开 |
| 空间锁版本 | 场景图版本、修复图版本（以用户确认的修复图为准） |
| 声线 | 每角色已定声线句（逐字复用，不重写） |
| 时长预算 | 每段台词秒数、动作秒数、反应秒数、余量、结论（够用/勉强/不够） |
| 已查专项 | 已进过的专项文件、命中条件、已定结论 |
| 已通过检查 | 规范检查表里已通过的项、对应段号、对应版本 |

记忆规则：

- 规则、固定空间与声线可缓存；动态状态随事件更新。某项按同版实际稿件核过且输入、上游依赖未变，才可复用通过结论；“已读规则”“已填表”不等于成稿已通过。
- 用户只改某段 → 只把该段及其依赖段标脏，只重算脏段；其他段的已通过项继续有效。这与 SKILL.md“局部修改只重写受影响段”一致，只是把范围从“重写”扩展到“重算”。
- 缓存规则解释，不缓存与当前条件不符的选镜、运镜或人物状态。
- 成稿校验先逐镜核对受影响段的全部相关人物和道具，再核跨段接续；局部改动包含新增动作与原全程锁、排除句、素材清单的冲突。发现同类问题时审查其余适用处，未授权重写的只报影响，不等用户再逐镜找错。

减负来自规则不重复读取、未受影响结果不重算；不能用跳过段内人物状态检查换速度。

## 五、排除注入只做一次

- 注入点唯一：seedance-2-5-adapter.md 第十一节，在写段时把剩余风险压成末尾一句排除，不粘贴八层全文。
- 专项文件不再各写排除句：需要排除时只在工作状态里记一条风险，写段时统一注入；注入后记入已通过检查，校验阶段只核对“已注入、未重复、未矛盾”。
- 默认每段“不要字幕、水印文字”仍按 adapter 规则；用户明确要求某段生成文字时只覆写该段这一条（见 opening-ending-title.md）。

- 声线：dialogue-scene-continuity.md 第一节第 2 条已补限定——年龄、性别、口音仅当剧本或已有角色信息给出时才写；未给的只写可推断音色、语速或标待确认，不编造。此后声线所有者为 SKILL.md 确认政策第 3 条，dialogue 文件不再与之冲突。

## 七、同场合并与节奏（分支实验，借鉴上传包 v0.3.28 的 R04A / I04 / R02A.10，按本 skill 的 30 秒上限和剧本保护改写，未实测）

本节只改生成段的切分和时长编排，不改剧情、台词、顺序、揭示节点；“合并”指合并生成段，不指合并剧情事件。SKILL.md“不删除、不合并”仍管剧情事件，不被本节覆盖。

1. 同场连贯、无时间跳时可合并，换说话人、机位或简单动作不机械拆段；30秒是上限，不是装满目标。先检查第八节的状态链、通路与镜头覆盖，人物对象转换、跨空间或关键交接集中导致负载过高时可在自然切点拆段。原稿锁定的镜头与动作保留；不靠减剧情或隐藏结构冲突省时。
2. 并行不重复计时：可同时发生的对白、行动、接收反应共用一个窗口，只计一次；必须先后的过程分别计时，不能取最长一项掩盖串行过程。倾听反应随对方的话连贯发生，不给每句机械附加独立反应时长，不等到句末才启动。
3. 辅助短镜只试排：承担一次简单确认的辅助插镜或短反应，可从约 0.5–1.5 秒试排，这是可调起点，不是每镜配额、硬性上限，也不套用于完整台词、复杂动作或原稿规定的停顿。
4. 段尾留白：每段总时长内先扣出 0.5–1 秒剪辑留白，再安排本段剧情、对白、关键节点；留白计入 4–30 秒总时长，不另加在上限之外，不按每镜另加。留白前完成必须听清的对白、必要阅读、关键动作节点；留白只写已成立状态的自然延续（画面、反应、必要运动、相关环境声与动作声），不新增对白、揭晓、关键事件，不自动黑屏、淡出、静帧、全员定格或静音。
5. 滚动预算：无指定总时长时，按场景逐段累加紧凑制作估时，每完成一个剧情场景段落重算一次；估值不是必须填满的配额，内容少就主动缩短或与相邻连贯内容合并，不用空镜、慢推、逐人反应或无意义动作填时。交付前按本节收紧冗余窗口，再重核原文覆盖与台词可完成性；缩短只能来自呈现调整，不能删原稿内容。
6. 每镜参考时长不是每段时长：camera-grammar.md 的大远景 3–5 秒、全景 2–4 秒、中景 2–3 秒、特写 1–2 秒，只用于单镜试排，不能直接当成一段的时长，更不能据此把一段拆成多段。

## 八、逐镜人物状态与复杂场身份锁（分支修正，2026-11-04）

转头/转身改变互动对象、进出场、道具交接、跨空间、隐藏/揭示或人物重新入画时，按事件维护相关人物状态；人数不是门槛。同场≥4人时覆盖所有影响接续的人物。普通两三人固定对话无状态变化，只写必要站位，不强制另建表或拆反应镜头。

先定固定地标、通路和人物关系，再按原稿事件依次更新状态，最后选能呈现它的机位与时长。内部可用短记或表，不要求用户填表；写段时将结论放入现有站位设定、时间戳和贯穿要求，输出模型需要的事实，不输出导演推理、版本留言或“先复核上一镜”这样的检查指令。

| 节点 | 内部记录与写段要求 |
|---|---|
| 进入状态 | 每人实际地标位置、坐站/支撑、身体朝向、头向/视线目标、占手/持物；固定椅子身份与朝向单列，不能与人的头向混为一项。已离场、尚未到场与在场画外分开 |
| 事件变化 | 谁因何触发，从何状态经何动作到何状态；只更新变化项，其余有效状态继承。切镜本身不改变物理状态，普通眨眼等无关微动作不建账 |
| 互动对象转换 | 决定临时转向何时结束、接下来保持原目标、回转或看新目标；用当前目标与空间几何决定转眼、转头、转上身还是移动，不规定换对象必转身。原稿明确持续盯住时保持；固定木椅不自动转成转椅，头身变化不带动家具 |
| 非主体与可见性 | 画外人物仍可能按已写事件行动，不冻结也不自行换位。每镜分别判断景框外、遮挡、已离场；景框变化可让原已在场者可见，隐藏揭示才需对应触发。切回中远景时补相关非主体的当前地标、姿态、头身朝向与持物，不能只写当前主体 |
| 进出路径 | 明确谁从哪个人的旁边或哪个地标起步，经同一已定门洞/通路到何处停下；开门与跨门槛顺序可达，门外等候者不直接由室内画外出现。无需每次同框所有人，所选景别应能呈现该镜承担的动作节点 |
| 连续与省略 | 连续镜头按实际路程和串行动作估时。普通剪辑可在起步/进入后切到同一路线的到达与交接，明写切点和到达位置，省去非关键路程；不能只靠“已到”掩盖未知通道、改变已定入场门，或删掉原稿指定的完整过程/长镜头。原稿未锁的普通机位与节奏可直接设计；用户锁定的时长确实装不下时按确认政策处理 |
| 交接与手别 | 接触和持有转移写清施事：谁递、谁接、谁先握稳、谁释放、最终归谁。交互换主语重写人名，不全局禁代词。普通接件站侧与手别按已定几何设计，已有明确手别不改；不要求用户来指定可自定的制作细节 |
| 空间边界 | 门洞、门扇、内部开口各按用途与状态区分；“唯一对外入口”不等于内部无通道。只用剧本、有效场景图与空间锁支持的结构；未见图外区域保持未知，不造门或补背景。剧情已写图外门时注明依据；无法确定关键通路时标受影响处待确认，不把原稿出门降级为停在门前冒充完成 |
| 画外互动 | 已在场但画外的人可按距离、视线和遮挡参与对话；门内外可隔已定开口说话、相望。递物须有可达的接触路径。未定人物、已离场者不能无依据参与；不可见不等于不在场 |
| 结束与接缝 | 每个关键变化落到结果，下一镜读当前状态；段末保留下一段需要的事实，跨段发生变化也须有动作或明确省略依据。不能只核段首/段尾相等而漏掉段中跳位 |
| 素材分工 | 每段独立上传编号；脸/服装/结构/光线按有效素材各自分工，同人多图不变分身。未收到或未查看的图不称已验，不能把旧稿里的“已裁/已上传/已修复”复制为本轮事实 |

**写完后沿事件逐镜回放一次**：检查所有相关人物的状态是否可达，机位、构图与左右是否匹配，起点/门槛/落点是否同一路线，交接主体是否明确。把全程锁、局部动作和排除句对照：只把真不变量写入贯穿，变化状态写窗口；旧锁与新动作冲突时同步修正，而非两句并存。只将剩余实际风险交适配模块注入排除，不写项目专名作通用规则。

例如，甲坐固定椅与乙谈话，转向门外丙后，丁从丙旁入室递件：先决定甲在交谈结束后继续看丙还是转回乙，并在相应窗口落实；丁经同一门槛起步、到乙侧停稳再交接。若只拍乙的近景，甲留在画外仍按已定动作更新，回到中景时写出甲当前朝向。这里没有默认转椅、没有要求全部步行同镜，也没有要求甲一律回转。

## 九、机位代码处理（分支实验，2026-11-03，文本改稿经验，未作视频验证）

1. 机位代码只作工作稿对照，不进提交正文。提交正文的每个时间窗口开头必须写完整机位句：机位在哪、朝哪看、什么景别、主体是谁、固定还是运动；光向由段机位说明与场景空间锁兜底，不逐窗口编造左右。
2. 工作稿中，每段的参数、制作参考、上传清单之后，同级追加一行“机位代码对照（工作稿，不提交）”，列本段用到的全部机位代码及无码机位（如室内/门口机位）；该行在提交正文块之外，不作为上传清单的子项，不进模型输入。
3. 代码按段独立定义，不跨段继承；同一代码在不同段含义不同时，按本段定义展开，不合并为全局编码表。时间窗口不得只写代码，也不得只写“中全景”而不写位置方向。
