# 参考素材准备：场景图与人物资产图

用户提供或计划制作场景设定图、人物设定图（多视图、服饰细节、道具）、平面图、九宫格时读取本文件，用于在生成前检查和处理参考素材，并在素材指代中写清分工。

来源：用户提供的场景一致性视频教程（俯视图、场景九宫格、720° 全景图、人物资产图），以及用户的两张设定图实例（多角度场景设定图、人物多视图设定图）；逐条对照《Doubao Seedance 2.5 提示词指南》（下称指南）和《Seedance 2.5 教程》（下称教程），标注“官方写法”或“推断”。

## 一、官方对参考素材的要求

1. 数量：单次最多 50 个参考素材，其中图片最多 30 张；视频最多 10 段、总时长不超过 30 秒；音频最多 10 段、总时长不超过 30 秒。（指南“素材输入建议”）
2. 主体数：主体图 1–8 个效果较好，9–12 个稳定性下降。主体包括人物、动物、道具、场所。（指南）
3. 多视图：1–5 个主体时，单视图、多视图均可；超过 5 个主体时单视图更稳定，需要多视角时拆成多张不同视图分别输入，不要一张图包含多视角。Seedance 2.5 支持多视图主体参考（2.0 不建议）。（指南）
4. 映射写在文本里：按上传顺序编号，每个素材在文本中绑定；不要只在图片上写名字做映射，容易导致多人混淆或重复角色。（指南）
5. 分工具体到参考什么：部分参考要写明参考哪一部分，并写明不采用什么。（指南、教程）
6. 图上不要写太多字：指南对宫格分镜的建议是“不推荐在分镜图上写过多文字”，并推荐简约线稿。
7. 真人人脸：Seedance 2.5 不支持直接上传含有真人人脸的参考图 / 视频，平台另有肖像使用方案。（教程“使用限制”）

## 二、场景与人物资产图的关系

强关联，但关联写在提示词里，不靠把两者画进同一张图：

1. 各管一块：场景图只放空间（不带人）；人物图只放人物（排除棚拍背景）。（官方案例：“image2 用于环境构图……image3 主体 1 角色外观参考”）
2. 在提示词里绑定：写谁在场景的哪个位置、什么姿态、朝向，身高用场景里的物体做参照（官方案例：“比走廊画面中的门低一个头”）。
   多个角色同框时，素材指代里把每张角色图同时绑定到画面位置，例如“图片1是新郎，对应画面左侧站着的男人；图片2是新娘，对应画面右侧坐着的女人”，排除内容加“两人互相串脸”。（推断，按官方“文本绑定”“避免角色对应错误”原则补充）
3. 需要最稳时做“场景初始图”：先用出图工具把人物放进场景，得到人物、站位、光线都正确的一张图，用官方首帧方式输入（“图片3为首帧”或参数 role=first_frame）。（官方能力；做图方法属于前期流程）
4. 首帧图按用途选输入方式：
   - 精确定格确认：画面必须和图完全一致，用参数 role=first_frame。会锁定宽高比，严格对齐首帧图。（官方写法）
   - 动作中段接续：首帧是上一段动作进行到一半的画面，例如手已碰到门把手。用 first_frame，并在第一个时间段写清动作从哪个阶段继续，见 `references/action-focus-crowd.md` 第一节。（经验）
   - 只作构图参考：只要构图和氛围相近，用 role=reference_image，再写“图片 N 为首帧”。不锁定宽高比，效果相近但不完全匹配。（官方写法）
5. 生图和生视频分开写：
   - 首帧图、尾帧图、场景初始图、分镜图只表现“当前这一瞬间”，出图提示词写：人物与固定服装 + 景别 + 人物在画面中的位置 + 当前动作（一个） + 场景与光线。
   - 一张图不同时表现几个动作。例如“拿钥匙、出门、上车”要拆成几张图或几个时间段，不画进同一张图。
   - 视频提示词再写动作：从什么动作开始、朝哪个方向、到什么状态结束（起始状态、运动轨迹、结束状态）。
   - 首帧图里人物已经在做的动作，视频第一个时间段从这个阶段继续，不重新起手。
   - 依据：指南首帧 / 首尾帧生视频；“每个镜头均需保留其起始状态、中间运动轨迹及结束状态”；“不推荐在分镜图上写过多文字”。“一张图只画一瞬间”是经验。

## 三、多角度场景图

- 场景设定图拼了多个角度时：本段主体（人物 + 道具 + 场景）总数不超过 5 个，可以整张上传；超过 5 个，按角度裁成单张分别上传。（按官方主体多视图规则推断）
- 每个角度都在素材指代中写明视角，例如“图片 4 是同一堂屋从床边看向门口的视角”“图片 5 是同一堂屋从门口看向床和桌子的视角”。（官方写法：分工写明参考什么）
- 特写格（道具、局部陈设）是道具参考，按 `references/scene-prop-continuity.md` 绑定为场景中的同一物体，写数量。
- 生成某个镜头时，只上传与该镜头机位相关的角度，不必每段都上传全部。（推断）

## 四、图上的文字

参考图上的文字可能被模型画进视频。图上文字在出场景图、道具图时管控，不在视频提示词里处理：

1. 设定图的标题栏、编号、图注、平面图标签、指北针：上传前裁掉。（官方建议“不推荐在图上写过多文字”；裁图是推断的稳妥做法）
2. 场景中作为布景的文字（喜字、对联、招牌、书脊、纸上手写字）：出场景图、道具图时就决定怎么画，例如画成“红色剪纸喜字图案”，或不画可读文字。视频提示词的素材指代不再写“图片 N 中的文字只保留色块和形状，显示为不可辨认的图案”。
3. 不在参考图上写人名、角色编号代替文本映射。（官方写法）

## 五、平面图、俯视图、全景图、九宫格

先看官方的反例：指南“复杂任务效果不稳定”案例中，输入带轨迹标注的图片后，输出视频里出现了红色轨迹线；另一个案例专门做编辑任务移除“红色线条，红色数字，红色箭头”。可见图上的标注、箭头、色块会被模型画出来，只在文字里写“不采用”不保险。

各类图继承什么、不继承什么：

| 图的类型 | 继承 | 不继承，需要处理 |
|---|---|---|
| 场景图 | 空间结构、陈设、光线方向、主色 | 图中的人；标题和图注要裁掉 |
| 人物图 | 脸、发型、服装、配饰 | 棚拍背景、展示用的姿势 |
| 道具正反面图 | 一件道具的外观 | 不是两件道具；写“图片 N 是同一只木匣的正面和背面” |
| 同一场景的多角度图 | 同一个空间的不同视角 | 不是几栋建筑；逐张写视角 |
| 平面图、白模、动线图 | 布局和走位 | 颜色、箭头、编号、标签；上传前去掉，或转成文字 |

处理标注的顺序：
1. 上传前删掉标注。（推断）
2. 转成站位文字。（推断）
3. 必须用带标注的图时，按官方做法拆成两步：先生成，再用编辑任务移除标注。（官方写法）


- 平面图、俯视图：官方文档没有把平面图作为场景参考的写法。优先把它转成文字写进站位设定（谁在画面哪一侧、动线从哪到哪）；需要上传时单独一张图，写“图片 N 只参考空间布局和动线，不作为画面内容，不生成俯视画面”。（推断，需试片）
- 官方的“九宫格”是分镜九宫格，用于镜头顺序、景别和运镜节奏，不是场景多角度图。宫格图不会严格对齐分镜，需要严格对齐时用多关键帧（“以图片 x 至图片 x 的顺序作为关键帧”）；宫格建议 15 格以下，推荐简约线稿。（官方写法）
- 720° 全景图、360° 环绕视频截图：属于制作多角度场景图的前期方法，官方未提及。截图时选变形小的区域，裁出的每个角度按第三节单独标注。（推断）

## 六、人物设定图（多视图、服饰、道具）

1. 一个角色的正侧背、多角度头像、服饰细节拼在一张图里可以使用（1–5 个主体时）。（官方写法）
   - 按本段计数：人物、道具、场所都算主体。本段主体超过 5 个时（例如四人同场加场景图和道具图共 6 个），人物图也改用单视图（单张全身或头肩），不直接上传九视图。（v1.29，按官方第一节第 3 条落实）
   - 上传清单只列已经处理好的文件。还没裁图时，在上传清单该项后写“待裁成单视图”，并在诊断中列为生成前必做，不把原始多格板直接列为上传素材。（v1.29）
   - 多格人物板直接上传时，模型可能把板上两个全身视图生成成同一人物的两个分身；四人以上同场、单人站立全身入画时风险最高。（经验，第31集试片）
2. 检查无头、缺肢的服装展示格（例如只有大衣没有头的正面图）：换成完整人物，或裁掉该格，避免生成无头或残缺人物。（推断）
   只有半身肖像、没有全身图的角色，要拍全身或走动镜头前，先补一张全身或正侧背设定图作为参考，否则下半身和服装下摆容易漂。（推断）
3. 素材指代写“图片 N 只参考人物的脸、发型、服装和配饰，不采用白色背景”。（官方写法：写明不采用什么）
4. 图中附带的道具（烟斗、怀表、银盒）要在文本中绑定：“图片 N 中的烟斗是他的随身道具，只在第 X 秒他取出时出现”，否则模型可能让道具一直在手里。（推断，按官方“文本绑定”原则）
5. 服饰细节格（面料、纽扣、袖口）可以保留，用作近景和特写的质感参考；写“图片 N 的面料细节用于近景”。（推断）
6. 写实风格的人脸可能触发真人人脸限制；必要时改用平台肖像方案或风格化形象。（官方限制）
7. 一个人物用了多张图时，写明是同一个人，例如“图片 1、图片 2 都是秦秀莲”，并加官方约束“同一画面中仅保留单个对应角色，不出现角色重复复刻”。（官方案例约束 + 道具同一写法的延伸）
8. 只借用某个属性用到另一个对象上时，写明属性和目标，例如“图片 4 只参考布料的纹理和光泽，用在秦秀莲的外套上，不采用衣服款式、模特和背景”。不写目标，模型会把整件衣服或模特一起带进来。（经验；按官方“写明提供什么、不采用什么”写全）
9. 同一人物有多个状态、每个状态一张资产图时（换装、受伤、年龄变化等）。官方没有专门写法，以下按官方三处内容推断：素材指代写明用途（指南“素材可能指向同一个或者不同的主体”）、关键帧分阶段标注（小女孩案例“3-5s（参考 <3pic>）”“角色外形与各阶段的关键帧保持一致”）、按首次出场顺序一一对应（指南“角色对应错误”）。
   - 素材指代里每个状态单独绑定，名字后用括号写状态，并写明是同一个人：“鹿知遥（红嫁衣）@图片1，鹿知遥（摆摊布衫）@图片2，图片1、图片2是同一个人，同一画面中仅保留单个对应角色，不出现角色重复复刻”。
   - 一个生成段里只出现一种状态时，只上传这个状态的图，不上传其他状态（最稳）。
   - 一个生成段里状态会变时，在时间段开头标注这一段用哪张图，例如“0-6秒（参考图片1）……6-12秒（参考图片2）……”；状态变化本身写成看得见的动作，例如“她把布衫套在嫁衣外面”“额角出现一道血痕”，不直接跳变。
   - 时间段里仍只写名字，不重复 @；状态括号只写在素材指代里。

10. 编号只用本段上传顺序的“图片 N”：素材指代和正文里不出现对话或文件名里的其他编号（如“用户确认图3”“本次图2”“原图1”）。这些编号对模型来说会被读成本段的图片 3、图片 2，把人物图和场景图对应错。需要说明“这张场景图是哪一版”时写在文本框外的上传清单里。（v1.29，经验：第31集稿正文混入讨论用的旧图号，图片 1–3 实际是人物）

## 七、素材指代示例

```
素材指代：祁家堂屋@图片1，祁家堂屋床边视角@图片2，新郎@图片3，新娘@图片4，空木匣@图片5。图片1只参考空间结构、家具摆放和烛光（标题栏和图注已在上传前裁掉，喜字和对联已在出图时画成图案）；图片2是同一堂屋从床边看向门口的视角；图片3、图片4只参考脸、发型和服装，不采用白色背景；画面中始终只有一只空木匣。
站位设定：新娘坐在画面右侧床沿，面朝画面左侧；新郎站在画面左侧桌边，面朝画面右侧，比床边的帐柱低一个头。
```
