# 项目状态与变更接续（v1.36）

来源：用户提供的《AIGC漫剧项目圣经》，以及用户2026-10-27确认吸收的轻量状态管理方案。属于工作流设计，不是Seedance官方能力或已验证的防穿帮保证。只维护当前提示词及后续接续需要的事实、状态和依据。

## 一、何时使用

- 同一场戏跨生成段、跨集复用资产，或本轮修改会影响其他提示词、参考图时使用。
- 用户提供项目圣经、项目设定卡、状态记录，或材料中同时存在多个版本、候选与实际生成结果时使用。
- 单个独立片段没有接续依赖时，直接用当前上下文核对，不另建整本项目圣经，不要求用户填表。

## 二、三类资料与两种状态

资料类型分开记录：
- **故事事实**：剧本与用户确认的身份、事件、道具归属、发生顺序。
- **呈现设计**：本次机位、构图、站位路线、资产版本与允许调整范围。换机位改变画面左右，不自动改变实际位置。
- **产物观察**：实际图片、视频中可见的结果及反馈。没有亲自查看的结果注明“转述，待核对”，不写成已验看。

每条关键记录分别标明：
- **采用状态**：锁定／工作设定／提案／未知／废弃。锁定来自用户或已确认原稿；工作设定是本次采用的呈现设计；提案尚未采用；废弃记录保留替代关系。
- **验证状态**：文本核对、静态图查看、视频验看分别记录“未核对／已核对及结果”，并给出对应版本或文件。文本通过不代表图片、视频通过；某张图查看通过不代表整段视频通过。

文件名“最终版”、较新的修改时间、图中偶然出现的持物或站位，都不能代替确认或验收。用户明确接受生成结果作为新设定时，记录其确认范围及替代关系，再检查依赖；未被接受的偏差只记为问题，不回写成故事事实。

## 三、读入最小上下文

1. 先找用户指定的当前项目记录及本轮明确修订；仅取当前集、场、段和相关人物、物件、地点的有效记录。
2. 有已有ID与名称映射就复用，例如“PROP-04＝铜钥匙”；同一实体改名保持ID。没有跨文件重名风险时直接用稳定名称，不为建账给所有物体编号。
3. 核对来源角色：人物资产控制已确认造型，场景图控制其已核对的结构，剧本控制事件。素材不因文件较新而自动覆盖已确认剧情；提案不因写入候选提示词而升级为采用。
4. 同级确认互相冲突且无法由本轮明确修订消解时，指出冲突及受影响范围，只询问决定当前执行的缺项；其他内容继续。普通未知信息不影响本段时保留未知，不补设定、不追问。

## 四、记录本段状态变化

记录按需用短段落或简表，以下内容可合并，不强制空栏：

| 内容 | 记录什么 |
|---|---|
| 依据与范围 | 当前剧本、资产或用户修订的版本／位置，集场段及故事时点，允许修改范围 |
| 进入状态 | 影响本段的位置、姿态、持有物与手别、重要情绪、已知信息及环境状态 |
| 本段变化 | 谁因什么触发，经什么必要动作或路线，改变了哪个状态 |
| 离开状态 | 下一段必须接住的结果；不把人物全身姿态或普通表情固定不动 |
| 采用与验证 | 资料类型、采用状态，以及文本／静态图／视频分别核到哪一版本 |
| 修改影响 | 受影响的后续段、参考图或资产，需改／需重验／已同步，以及尚未完成的原因 |

只追踪会影响理解与接续的内容，不逐次记录眨眼或无关微动作。回忆、录像和现实按各自故事时点读取，不能用现实最新状态覆盖过去。

动作、手别与跨镜头检查仍用 `dialogue-scene-continuity.md` 第二、三节和 `scene-prop-continuity.md`，关键帧时点仍用 `keyframe-workflow-notes.md` 第三、四节。本文件统一来源、采用、验证和保存方式，不再复制动作规则。

## 五、修改、保存与恢复

- 先写候选并核对剧本、图文、时序和物件归属，再更新本轮已核对的状态。候选稿不能提前覆盖当前有效记录，用户锁定项也不因本轮文本检查而失去锁定。
- 变更记日期、来源、新旧值、生效集场段与受影响对象；被替代项标废弃并指向新记录，不抹除历史。后续状态逐项检查依赖，不把旧记录整段复制为已通过。
- 只修改本轮授权的段落与资产；其余依赖标“待修改／待重验”，不自动重写、生成或宣称已同步。轻量记录是交接依据，不是后台任务或自动跨会话记忆。
- 优先更新用户指定的项目记录文件。没有现成文件、且任务在可写项目目录中执行时，在项目目录保存一份 `项目状态记录.md`；已存在则读取后增量更新，保留来源和变更历史。同目录承载多个项目时使用各自项目子目录，不混记。记录内包含当前有效状态和本次变更影响即可，不额外创建完整世界观资料库。
- 无法写文件或当前任务只有对话时，在提示词正文外交付精简状态记录，并明确“尚未保存到项目文件”。下次没有取得该记录时，只从可访问材料恢复并说明缺项，不假装已读过或自动记住。
- 视频提示词只写当前段实际需要的具体开场、动作和结束状态；记录ID、确认标记、日志与检查结论留在正文外，不新增“项目圣经”投喂栏目。交付时简述变更影响和未决项，不重复整张检查表。

## 六、应用示例

已确认S2结束林岚左手持唯一铜钥匙（PROP-04），S2文本核对通过；名为“最终版”的生成图尚未审看，工作人员反馈疑似右手持钥匙。

当前有效故事状态仍为左手持钥匙；图像条目单列“转述，待核对”，不能标静态图通过。S3文字可从左手持钥匙开门、右手扶门开始；该候选图不直接作为已核对的接续依据。

用户随后明确改成S2末将钥匙交给周砚并由其持至S5：更新S2交接与离开状态，列出原S3林岚开门、原S4递回钥匙、原S5林岚放入抽屉及相关旧关键帧的依赖冲突。本轮只获授权改S2时，后续标待修改／待重验，不补写隐藏交接来消解冲突。
