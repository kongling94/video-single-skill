# 自检索引

普通交付在内部按 production-core.md“交付前内部检查”核对，不必额外读取本文件。本文件只是该规范检查表的索引，不是第二套执行：不重新跑覆盖、时长、空间核对，只定位某项的权威文件。执行顺序、状态记忆、脏段重算、单一所有者表见 references/execution-flow.md。用户要求审计或复杂专项时用下表定位对应规则，不把全库抄成勾选清单。输出遵守 SKILL.md 的交付结构，默认一句核对结果及未决项；用户要求逐专项结果时才展开。

## 复杂场身份锁附表（分支实验，仅触发时查，定义见 execution-flow.md 第八节）

触发条件：同场人物 ≥ 6 人，或有埋伏、隐藏、跑动、跨位置移动时。本表只是索引，不另建第二套执行；权威定义在 execution-flow.md 第八节，轴线与视线在 scene-blocking-axis.md 第九、十节。

- 每段开头是否写了进入表（位置、姿态、是否可见、持物、注视目标），不在场的人是否写明画外在场或尚未出现？
- 暗室内、墙后、转角后的人是否写成未出现、不可见，成为可见是否有单独触发（声音、灯亮、现身喝止），触发前是否出现在可见门槛处？
- 换位路线是否写了起点 → 地标 → 终点和结束站位，路线起点是否对照已定站位核过（不是从门口起笔的错路线）？
- 每段末的结束状态是否等于下一段的进入状态，离开状态不一致的段是否标脏？
- 素材指代是否写清每图参考范围、同一个人多图说明、每段独立编号、场景图视角与光线分工？
- 排除内容是否写了串脸、位置互换、瞬移、错误人物发声、民警从场外入口进等本段实际风险，而不是一句空话？
- 带标注的动线图、俯视图是否只作文字推导（未上传），纯轮廓无文字图是否仍按分支实验条件（先实测、出问题停用回退），严格站位是否仍用关键帧或场景初始图而不是线稿代替？
